# Карта чтений и записей

| Сценарий | Операция | Частота | Ожидаемый объём | Задержка | Согласованность |
|---|---|---:|---:|---:|---|
| Заказы клиента | Чтение по customerId | Высокая | 5–50 документов | до 100 мс | Актуальное чтение |
| Активные заказы курьера | Чтение по courierId и status | Высокая | 1–30 документов | до 100 мс | Актуальное чтение |
| Поиск по статусу | Чтение по status | Высокая | 10–500 документов | до 150 мс | Актуальное чтение |
| Назначение/смена статуса | Обновление orders + запись events | Высокая | 1 документ + 1 событие | до 150 мс | Требуется согласованное обновление |
| История заказа | Чтение events по orderId | Средняя | 1–1000 событий | до 300 мс | Сохранение порядка событий |
| Аналитика зон | Aggregation | Низкая | 3–100 групп | до 1 сек | Допустима небольшая задержка |

# Пользователи и сценарии
1. Клиент создаёт заказ.
2. Клиент просматривает свои заказы.
3. Оператор назначает курьера.
4. Курьер меняет статус доставки.
5. Оператор ищет активные заказы.
6. Администратор смотрит статистику по зонам.
7. Оператор просматривает историю событий заказа.

# Сравнение моделей
MongoDB — документная модель: удобна для CRUD и агрегации по полям заказов.
Neo4j — графовая модель: удобна для сложных обходов связей клиент–заказ–курьер–зона.
Выбрана MongoDB, поскольку основные сценарии — поиск и обновление документов, а не сложные многошаговые обходы графа.
