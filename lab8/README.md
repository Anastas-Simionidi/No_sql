# DeliveryDB — система доставки заказов

## Требования
- JDK 21
- IntelliJ IDEA
- Maven (в IntelliJ встроен)
- MongoDB Server, запущенный локально на `mongodb://localhost:27017`

## Запуск
1. Откройте папку `DeliveryDB` в IntelliJ IDEA.
2. Дождитесь импорта Maven и загрузки `mongodb-driver-sync`.
3. Убедитесь, что MongoDB Server запущен.
4. Запустите `src/main/java/org/example/Main.java`.

Можно также запустить из терминала проекта:
`mvn compile exec:java`

## Что делает программа
- Создаёт базу `DeliveryDB` и коллекции customers, orders, couriers, zones, events.
- Создаёт индексы для идентификаторов и часто используемых фильтров.
- Загружает тестовые данные: 10 клиентов, 5 курьеров, 3 зоны, 20 заказов и 20 событий.
- Выполняет чтение заказов клиента, активных заказов курьера, поиск по статусу, изменение статуса, безопасную отмену, аналитику по зонам и чтение истории заказа.

Повторный запуск не дублирует исходный набор данных, если в коллекции customers или orders уже есть документы.

## Основные поля
- customers: customerId, name, phone, address
- couriers: courierId, name, phone, available, zoneId
- zones: zoneId, name, deliveryFee
- orders: orderId, customerId, courierId, zoneId, description, amount, deliveryFee, status, createdAt, updatedAt
- events: eventId, orderId, status, description, createdAt

## Ограничения и масштабирование
1. Локальный сервер является единой точкой отказа; для надёжности можно использовать replica set.
2. Аналитические агрегации на большой коллекции могут замедлять работу; можно использовать предварительно рассчитанные отчёты и отдельные аналитические узлы.
3. Для горизонтального масштабирования больших объёмов заказов можно рассмотреть sharding по zoneId или customerId после анализа распределения нагрузки.

## Архитектурное решение (ADR-001)
**Контекст:** системе доставки нужно хранить заказы, клиентов, курьеров, зоны и историю событий; основные операции — поиск и изменение документов, а также агрегирование статистики.

**Решение:** использовать MongoDB с документной моделью, Java 21 и официальный MongoDB Java Sync Driver. Заказы хранят ссылки на связанные сущности через идентификаторы; историю изменений храним отдельно в events.

**Альтернативы:** Neo4j удобна для сложных многошаговых обходов связей, но для преобладающих CRUD-операций с заказами документная модель проще. Реляционная БД обеспечивает строгие связи и транзакции, но требует более жёсткой схемы.

**Последствия:** быстро реализуются поиск, обновление и агрегация; целостность ссылок между коллекциями нужно контролировать на уровне приложения, а для масштабирования потребуется продумать шардирование и резервирование.

## Контрольные результаты
- После первой загрузки: 10 customers, 5 couriers, 3 zones, 20 orders, 20 events.
- Запрос заказов C001 должен вернуть 2 заказа.
- Запрос активных заказов R002 должен вернуть заказы со статусами ASSIGNED или IN_TRANSIT.
- После обновления O001 его статус должен быть ASSIGNED, а в events должна появиться запись.
- После отмены O020 его статус должен быть CANCELLED.
- Аналитика должна вывести группы по трём зонам.
