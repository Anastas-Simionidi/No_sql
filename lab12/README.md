# Лабораторная работа №12: Разработка и запуск воспроизводимого benchmark-сценария

**Дисциплина:** Проектирование и применение NoSQL-технологий  
**Вариант №01:** Каталог курсов (фильтр по `departmentId` и `semester`)

## Описание проекта
Репозиторий содержит скрипты и результаты воспроизводимого нагрузочного тестирования (benchmark) NoSQL-базы данных **MongoDB**. Цель эксперимента — измерить задержки (P50, P95, P99 latency), пропускную способность (RPS) и долю ошибок при выполнении поисковых запросов до и после создания составного индекса `{departmentId: 1, semester: 1}`.

## Структура репозитория
* `seed.py` — генерация 5000 синтетических документов в коллекцию `nosql_lab12.courses` с фиксированным `seed = 42`.
* `benchmark.py` — скрипт проведения closed-loop нагрузочного тестирования (уровни нагрузки: 1, 4 и 8 параллельных клиентов, по 3 повтора с предварительным прогревом).
* `plot.py` — обработка сырых данных и построение графиков зависимости P95 latency и RPS от числа клиентов.
* `results.csv` — исходные результаты всех замеров в табличном виде.
* `charts/` — папка с итоговыми графиками (`p95_chart.png` и `rps_chart.png`).
* `requirements.txt` — список зависимостей Python.
* `.env.example` — пример конфигурации подключения к БД (без паролей).
* `report.pdf` — полный отчёт о проделанной работе с планами `explain`, расчётами и выводами.

## Требования и установка
* Python 3.10+
* Локальный сервер MongoDB (порт `27017`) и консоль `mongosh`

1. Клонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone <ссылка-на-ваш-репозиторий>
   cd lab12
   ```

2. Создайте и активируйте виртуальное окружение:
   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # Linux/macOS:
   source .venv/bin/activate
   ```

3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

## Порядок воспроизведения эксперимента

1. **Генерация тестовых данных:**
   ```bash
   python seed.py
   ```

2. **Базовый замер (без составного индекса):**
   Убедитесь, что в `benchmark.py` указан режим `main("no_index")`, и запустите тест:
   ```bash
   python benchmark.py
   ```

3. **Создание составного индекса (в консоли `mongosh`):**
   ```javascript
   use nosql_lab12
   db.courses.createIndex({departmentId: 1, semester: 1})
   ```

4. **Повторный замер (с составным индексом):**
   Измените режим в `benchmark.py` на `main("with_index")` и снова выполните скрипт:
   ```bash
   python benchmark.py
   ```

5. **Построение графиков:**
   ```bash
   python plot.py
   ```

## Ограничения эксперимента
* Тестирование проводилось в режиме **closed-loop** (фиксированное число запросов на пул потоков) на локальной машине, поэтому при росте числа клиентов пропускная способность (RPS) упирается в ресурсы CPU/локального соединения, а хвостовые задержки (P95) растут из-за конкуренции потоков.
